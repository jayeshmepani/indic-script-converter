1. What lipimala does

Converts between scholarly Latin (IAST / extended Indic / ISO-style tables), Devanagari, Gujarati, and plain-English / Hunterian views. Visible Brahmic rendering is many-to-one—case, aliases, and normalization collapse—so exact recovery uses an envelope or an invisible metadata trailer.

1.1.0: first-class Devanagari/Gujarati → Plain-English/Hunterian APIs, source-aware inherent-schwa naturalization, and explicit handling for the supported Unicode 18 script repertoire, relevant Vedic/extended ranges, historic forms, Gujarati Arabic-transliteration marks, and format controls. Existing IAST → Plain-English/Hunterian behavior remains backward-compatible.

1.2.0: opt-in NATURAL morphology and phonology for Devanagari and Gujarati, plus SMART syllable vowel length. The default remains LEGACY. Plain English still doubles long vowels; Hunterian still collapses them when vowel length is omitted. Sanskrit and canonical Brahmic → IAST stay conservative. Bengali, Odia, Tamil, Telugu, Kannada, Malayalam, Gurmukhi, and Sinhala are outside this layer.

Supported directions

  • Latin/IAST → Devanagari
  • Latin/IAST → Gujarati
  • Latin/IAST → plain English / Hunterian
  • Devanagari / Gujarati → readable Plain English / Hunterian
  • Devanagari → IAST (canonical / smart / exact)
  • Gujarati → IAST (canonical / smart / exact)
  • Devanagari ↔ Gujarati (canonical / smart / exact)

Two recovery strategies

  1. TransliterationResult — keep the object / JSON and call restoreOriginal().
  2. Exact-source trailer — set embedExactSourceMetadata: true so the string carries a checksummed Unicode-Tag payload (LIT1:).

Envelope examples

Pass IastToDevanagariOptions for script output and IastPlainEnglishOptions for plain English. inputNormalization defaults to nfd and outputNormalization defaults to nfc. In JavaScript those fields sit beside options on the second argument. Dart, Python, and PHP pass the options object itself. toGujarati('Kṛṣṇa') returns કૃષ્ણ and takes IastToGujaratiOptions with the same fields.

import 'package:lipimala/lipimala.dart';

void main() {
  final script = 'Kṛṣṇa'.toDevanagari();
  print(script.rendered); // कृष्ण
  print(script.restoreOriginal()); // Kṛṣṇa

  print('Rāma 2.'.toDevanagari(
    options: const IastToDevanagariOptions(
      digitPolicy: IastToDevanagariDigitPolicy.convertToScript,
      punctuationPolicy: IastToDevanagariPunctuationPolicy.indicDanda,
    ),
  ).rendered); // राम २।

  final english = 'Rāma'.toPlainEnglish();
  print(english.rendered); // Ram
  print(english.restoreOriginal()); // Rāma
}

6. IAST → Devanagari (string API)

toDevanagariFromIast / to_devanagari_from_iast

  • string
  • optional metadata trailer
Parameters
Parameter Type Default
text string required
options IastToDevanagariOptions all defaults (§13)

When: you only need the rendered script string, or you will reverse later via metadata.

How exact reverse works: pass embedExactSourceMetadata: true, then call toExactIastFromDevanagari(tagged). The three reverse modes are in section 9.

Option examples

toGujaratiFromIast('Kṛṣṇa') returns કૃષ્ણ. It takes IastToGujaratiOptions; the fields match the calls below, with the Gujarati enum names. iso15919Core is the third profile. throwError raises on an unknown Latin letter. For kḷ, context and preferVocalic both yield कॢ.

import 'package:lipimala/lipimala.dart';

void main() {
  print('shiva'.toDevanagariFromIast()); // शिव
  print('shiva'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(
      profile: DevanagariRomanizationProfile.strictIast,
    ),
  )); // sहिव

  print('Raama'.toDevanagariFromIast()); // रअम
  print('Raama'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(acceptAsciiLongVowels: true),
  )); // राम

  print('oṃ'.toDevanagariFromIast()); // ओं
  print('oṃ'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(
      omPolicy: IastToDevanagariOmPolicy.useOmSign,
    ),
  )); // ॐ

  print('ə'.toDevanagariFromIast()); // ə
  print('ə'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(
      unknownLatinPolicy: IastToDevanagariUnknownLatinPolicy.bracket,
    ),
  )); // [ə]

  print('kḷ'.toDevanagariFromIast()); // कॢ
  print('kḷ'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(
      ambiguousLPolicy: IastToDevanagariAmbiguousLPolicy.preferConsonant,
    ),
  )); // क्ळ्

  print('sha'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(acceptPlainSh: false),
  )); // sह  (default श)
  print('xa'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(acceptPlainXAsKha: false),
  )); // xअ  (default ख़)
  print('swa'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(acceptWAsVa: false),
  )); // स्wअ  (default स्व)
  print('ā́'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(preserveVedicAccentMarks: false),
  )); // आ  (default आ॑)
  print('a  b'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(collapseWhitespace: true),
  )); // अ ब्

  final tagged = 'Kṛṣṇa'.toDevanagariFromIast(
    options: const IastToDevanagariOptions(embedExactSourceMetadata: true),
  );
  print(stripExactSourceMetadata(tagged)); // कृष्ण
  print(hasEmbeddedExactSource(tagged)); // true
}

8. IAST / Brahmic → plain English / Hunterian

Which Hunterian this is: simplified ASCII Hunterian, the map and signboard spelling. A long vowel is one plain letter, and consonant dots are removed. जान is Hunterian jan and Plain jaan. ट and त are both t. ड and द are both d. श and ष are both sh. An IAST call drops the macron in every profile, so jān is jan for Plain and Hunterian.

The 1954 Government of India standard keeps macrons (jān, kailāsh-nāth). The 19th-century Hunter spelling uses an acute accent (ján). Those spellings are outside this profile. Canonical IAST keeps the precise letters (jān, kṛṣṇa).

Two practical rules go further than the 1954 chart. Legacy Hindi Hunterian writes w after a consonant (Sarasvatī → Saraswati). Gujarati, and NATURAL Hindi or Gujarati, keep v. Hunterian drops visarga before a stop or sibilant (duḥkha → dukh; Plain keeps duhkh). NATURAL + SMART is a separate reading: with both set, Gujarati Plain and Hunterian return the same string.

toPlainEnglishFromIast / to_plain_english_from_iast

  • string
  • intrinsically lossy

ASCII-friendly transcription. Keep the envelope for exact source recovery. IAST input uses the legacy Plain-English/Hunterian policies; direct Devanagari/Gujarati input additionally tracks inherent schwas before applying language-aware Gujarati/Hindi deletion rules, with a Sanskrit no-deletion mode.

Direct APIs: toPlainEnglishFromDevanagari, toHunterianFromDevanagari, toPlainEnglishFromGujarati, and toHunterianFromGujarati, with matching list APIs and loss-aware result-envelope APIs such as toPlainEnglishFromGujaratiResult.

BrahmicPlainEnglishOptions controls language, schwa deletion, vowel length, terminal anusvara, Gujarati ʿayn rendering, jñ/ñ/glottal handling, Vedic-mark preservation, whitespace, and contextual v/w behavior. Since 1.2.0 it also accepts readableStyle (legacy or natural), vowelLength: smart, sentence-start capitalization, and exact readable-word overrides. Historic prishthamatra and short-AI forms, Vedic nasal/visarga signs, OM, Sindhi implosives, Konkani च़, Gujarati Sukūn/Shadda/Maddah and special nuktas are interpreted semantically instead of leaking raw source-script marks into ordinary readable output.

SMART runs only with natural. Closed monosyllables keep length (chaar, hoon, swaroop). Open particles and heavy clusters shorten (dharan, karine). An open ending keeps stem length (swaroopama, paasethi). A nasal coda keeps a peripheral vowel (hoonga). Sanskrit SMART still doubles every long vowel (shvetadveepa). With natural + smart set on both calls, Gujarati Plain and Hunterian return the same string.

Natural schwa keeps a vowel between p and an unaspirated t (राष्ट्रपति → rashtrapati). An aspirated થ / थ still contracts (શાપથી → shaapthi). Legacy गांधीनगर stays gaandheengar; natural Hindi is gandhinagar.

17. Dart-specific notes

The Dart implementation (package:lipimala) targets Dart 3.0+. It is usable in Dart applications and Flutter projects. It exposes both functional APIs and natural extensions on String. Option examples for each API are in the conversion sections above. Enum members here are natural, smart, and doubled.

  • Primary Barrel Import: import 'package:lipimala/lipimala.dart'; (exports all converters, options, enums, and result models).
  • String Extension APIs: Call 'Kṛṣṇa'.toDevanagari(), 'Kṛṣṇa'.toGujarati(), 'Kṛṣṇa'.toPlainEnglish() directly on String instances.
  • String Extension APIs: Dart uses extensions on String rather than wrapper/subclass return types. Envelope APIs return TransliterationResult; exact recovery is available through the result object or the metadata-aware reverse helpers.
  • Option Constructors: Options use named parameters with defaults: IastToDevanagariOptions(profile: DevanagariRomanizationProfile.extendedIndic, embedExactSourceMetadata: true).
  • Error Handling: Throws ArgumentError on invalid options or corrupted metadata trailers.

18. JavaScript-specific notes

The JavaScript implementation targets Node.js ≥ 20 and modern JavaScript environments using ES modules (ESM). Option examples for each API are in the conversion sections above. Enum members here are NATURAL, SMART, and DOUBLE.

  • Module Imports: ESM: import { toDevanagari, toDevanagariFromIast } from 'lipimala';
  • Dual Export Naming: Exports both camelCase (toDevanagariFromIast) and snake_case (to_devanagari_from_iast) aliases for all functions.
  • Flexible Options: String and direct converters accept new IastToDevanagariOptions({...}) or a plain object, with camelCase or snake_case keys. Envelope functions take { options, inputNormalization, outputNormalization }. Putting the option fields on that outer object does not apply them.
  • String Subclasses: String converters return instances of IastToDevanagariString, IastToGujaratiString, or IastToPlainEnglish extending native String, offering .toExactIast().
  • Error Handling: Throws standard TypeError or Error on bad arguments or metadata decoding failures.

19. Python-specific notes

The Python package (pip install lipimala) requires Python ≥ 3.12, utilizing modern type hints and dataclasses. Option examples for each API are in the conversion sections above. Use snake_case fields such as readable_style and vowel_length.

  • Imports: Main & direct script converters: from lipimala import to_devanagari, to_devanagari_from_iast, to_devanagari_from_gujarati
  • Function & Enum Aliases: Supports standard Python PEP 8 snake_case functions and camelCase aliases for cross-language parity. Enums inherit (str, Enum) and support both EXTENDED_INDIC and extendedIndic member access.
  • Dataclass Options: Options are Python @dataclass objects instantiated with keyword arguments: IastToDevanagariOptions(embed_exact_source_metadata=True).
  • String Subclass Returns: Returns IastToDevanagariString, IastToGujaratiString, IastToPlainEnglish subclasses of str with .to_exact_iast() / .restore_original().
  • Error Handling: Raises ValueError on invalid option configurations or corrupted metadata.

20. PHP-specific notes

The PHP port (composer require jayeshmepani/lipimala) requires PHP ≥ 8.3 with strict typing throughout. Option examples for each API are in the conversion sections above. Pass options with named arguments.

  • Namespace & Autoload: Namespace Lipimala. Import functions with use function Lipimala\toDevanagariFromIast;.
  • Dual Function Aliases: Supports both toDevanagariFromIast() and to_devanagari_from_iast() namespaced functions.
  • Final Readonly Options: Options are final readonly class instances with promoted constructor properties and default values. Options parameters are nullable (pass null for defaults).
  • Zero Runtime Dependencies: Pure PHP code with bundled Unicode 17.0.0 data tables; does not require mbstring or intl extensions.
  • Error Handling: Throws InvalidArgumentException on invalid parameters or failed metadata verification.
